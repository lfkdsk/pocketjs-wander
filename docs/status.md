# Feature status

This checklist describes what the standalone Wander repository ships today.
Pocket RPG Kit engine features remain tracked in the
[component status](https://github.com/lfkdsk/pocketjs-rpgkit/blob/main/docs/status.md).

| Feature | Status | Notes |
| --- | --- | --- |
| Endless generated world | Done | Wander streams deterministic chunks around the player with bounded residency, towns, landmarks, errands, a travel log, pooled rendering and automatic exploration. Its simulation is pinned at 60/30/20/4 Hz and across save/restore in `tests/wander-sim.test.ts`, `tests/wander-f1.test.ts` and `tests/wander-f2.test.ts`. |
| Character look pool | Done | Sixteen CC0 Ninja Adventure walkers in four build-time palettes provide 64 stable looks through on-demand CLUT8 tilesets; `tests/wander-looks.test.ts` pins identities and pixels. |
| Browser and desktop builds | Done | `bun run web` publishes Wander and Wander Online; `bun run desktop [wander|wander-online]` runs the native host. Both use the nested Pocket RPG Kit and PocketJS submodules. |
| Wander Online world and netcode | Done | Protocol v4 streams the deterministic world at signed absolute coordinates through `/ws/v4`, with server authority, prediction/rollback, epoch-safe reconnects, sparse AOI and an atomic 32-player admission cap (`1008/full` before focus mutation). A WELCOME4 capability bit negotiates six reference ticks per input packet (10 Hz) without changing the wire length; an old server falls back to three and a new decoder still accepts plain INPUT and three-tick batches. If the native transport closes between a gameplay frame and its queued close callback, the client now leaves the `1008` reason and retry policy to that callback instead of stopping the game loop; deterministic coverage includes monthly-budget `rest` and its 15/30-second slow backoff in `tests/wander-online-client-core.test.ts`. Sparse `REGION_STATE` deltas give every client the same wall-clock growth collision and shared improvements; recipient-only `PLAYER_PROGRESS` carries private landmark history. The hosted service retires the legacy frozen-window v3 door by default while retaining it behind a one-cycle switch. The default HUD shows world coordinates, the latest nearby first discoverer and current-room versus whole-service presence (`ROOM n · ALL m`); see `examples/wander-online/README.md` and the `tests/wander-online-*.test.ts` suites. |
| Wander Online compatibility and delivery cadence | Done | A v4 client that receives an incompatible welcome closes with the browser-valid private code `4000` and reason `upgrade-required`, stops retrying and gives the player an explicit upgrade message; the legacy server-originated `1008/upgrade-required` path remains understood for old deployments. An unreplayable prediction rebase closes with private code `4001`, clears stale state on the close callback and rejoins on the normal backoff. Local snapshots and remote FAR markers use independent deterministic frame deadlines, so changing snapshot frequency cannot move or suppress the fixed 20-frame FAR cadence; coincident deadlines send the snapshot first. See `tests/wander-online-client-core.test.ts` and `tests/wander-online-meet.test.ts`. |
| Wander Online gameplay under server authority | Done | Residents walk their routes as a pure function of the realm clock, the notice board and resident dialog use the single-player text generators, and the plaza action accepts or delivers errands through `COMMAND` frames the server validates against its own mover and clock. Each player's errand, helped and talked towns are a private journey (`PLAYER_JOURNEY`, recipient-only, persisted by the hosted server in a JSON row whose worst case is derived from the caps: 1874 bytes under a 2048-byte bound, with `mergeJourney` reconciling two sessions of one account); a town's plaza flowers are a shared improvement raised once even when several players finish the same errand together. Fast travel is the input stream's fast bit, bounded to the single-player speeds and confirmed by the authoritative snapshot; landmarks are sighted inside a fixed 15x8-tile box regardless of viewport. Reseeding and idle auto-walk are not available online (auto-walk is a menu opt-in). Display names are limited to the charset the 12 px name font bakes (ASCII and 3755 common simplified Chinese characters), so Chinese names render as glyphs in the HUD and name tags. See `examples/wander-online/README.md`, `tests/wander-online-journey.test.ts`, `tests/wander-online-journey-view.test.ts` and `tests/wander-online-cjk-font.test.ts`. |
| Cooperative delivery errands | Done | On servers that advertise `coopErrands`, a stable one-in-three subset of delivery offers requires two distinct account incarnations at the target plaza. Each player accepts and carries a private journey; READY persists for 30 seconds across disconnect/reconstruction, counts only still-present matching couriers, and settles one deterministic pair once. Both journeys record completion and the target receives one shared improvement. Recipient snapshots reveal only aggregate `saved/present/required` counts, never another identity or position. The loopback server supports live co-op without durable restart storage; the hosted server supplies persistence. See `examples/wander-online/README.md` (Cooperative delivery errands), `tests/wander-online-journey.test.ts` and `tools/wander-online-coop-demo.ts`. |
| Per-realm FIRST-finder board | Done | On servers that advertise `discoveryLeaderboard`, the Discovery panel ranks landmark FIRST facts per realm. Listing is opt-in and private by default: the caller always sees `YOU`, their rank and count, while the public page contains at most 20 opted-in display names. Toggling off removes the public row immediately, complete account deletion removes consent and attribution, and no online state, realm location, coordinates or account id enters the projection. The loopback server deliberately leaves this capability off because it has no durable identity store. See `examples/wander-online/README.md` (FIRST-finder board), `tests/wander-online-social-panel.test.ts` and `tests/wander-online-social.test.ts`. |
| Wander Online meeting others | Done | Admission places every player on a free, unblocked tile of a hashed ring around its anchor (32 players at once never share or block a tile); a client returns to the realm it was in and can mint an hour-long invite (`<realm>.<CODE>`, no account data) that the web page shares as a link, with explicit `WORLD FULL` / invalid-invite refusals and an "any world" menu action; players outside the AOI show as an edge marker with a compass octant and a distance band only; five preset emotes (one byte, rate-limited, AOI-only, never stored) draw a bubble above the name tag; there is no free-text message. The local player's white nameplate has a four-sided dark pixel outline that remains legible over grass, sand, snow and water edges; direction-isolated framebuffer probes cover each side independently. See `examples/wander-online/README.md` (Meeting others), `tests/wander-online-meet.test.ts`, `tests/wander-online-meet-view.test.ts` and `tests/wander-online-journey-view.test.ts`. |
| Wander Online social and self-service | Done | The SELECT menu's DOWN action opens a bounded controller-first panel for friends, worlds and personal data. Same-realm requests become mutual friendships only after acceptance; accepting, declining, cancelling and idempotent removal use stable account identities, while invite redemption creates a pending request only. Passive disconnect publishes an empty nearby roster immediately. Presence and exact realm are visible only to mutual friends, and the privacy switch exposes hidden status without a realm. World choices disclose coarse population bands and join an explicitly selected realm without falling back when it is full. Responsive one-line copy uses a conservative 8 px display-cell budget in phone portrait and landscape layouts, and the compact Friends footer remains clear of its page counter. The wide 1x landscape panel narrows between the hosted d-pad/action overlays without squeezing its detail column. Self data includes the profile, friend/request counts and per-realm journey summaries; profileless legacy accounts see an explicit empty summary from character creation and can delete without first creating a character. Complete deletion removes account and realm-owned data before the client clears its ticket and signs out; partial failure remains signed in for retry. `bun run shots:social -- <output-directory>` captures the Friends, Worlds, My Data and delete-confirm views at 480x272 and 960x544 plus 3x review copies. See `examples/wander-online/README.md` (Friends, worlds and account data), `tests/wander-online-social-panel.test.ts` and `tests/wander-online-meet-view.test.ts`. |
| Wander Online accounts | Done | The web page supports GitHub OAuth, one-use token exchange, persistent session tickets and character creation. Display names are 1..12 code points of the shared name charset, validated by the same `validateName` on the client (before a CREATE is sent, with the reason shown in English and Chinese), the local server and the hosted server. The creation grid is generated from the charset's ASCII part, so it offers exactly the characters a name may contain; Chinese names are typed into the player page's text box beside the Sign out button (any input method) and handed to the game through the auth hooks. Desktop supports six-digit profile linking; bilingual web sign-out delegates to the same game path as in-game sign-out, clears persisted credentials, and immediately follows runtime page-language changes. See `examples/wander-online/README.md` (Names and the name font), `tests/wander-online-name-input.test.ts` and `tests/wander-online-auth-sim.test.ts`. |
| Wander Online mobile web controls | Done | The web manifest exposes every gameplay and menu action needed for social navigation, emotes, invites, character management and sign-out, not only movement and confirm/cancel. At 390x844 portrait and 844x390 landscape, page controls meet a 44 CSS-pixel touch-target floor; landscape immersive game-pad controls stay at the side edges clear of the status, bottom HUD strips and both the social home and Friends panels, while name and invite panels leave immersive play before exposing their page-owned text, Copy and Close controls. After `bun run web`, `bun tools/wander-online-mobile-verify.ts --out <output-directory>` drives the real OAuth/name/create/social/emote/invite/copy/close/sign-out flow in Chrome with DPR 3 touch emulation, checks both projected social panels against every visible game-pad control, and retains screenshots plus a machine-readable layout report. |
| Hosted service operations | Partial | The Cloudflare server enforces room, rate, origin, session and monthly-budget limits. Deployment and production monitoring live in `pocket-online-server`; the local Bun server is loopback-only and enables guest access only with `--allow-guests`. |
